## 2. 入力(見どころの手がかり)

| # | 入力 | 取り方 | 時刻 |
|---|---|---|---|
| ① | Twitch のストリームマーカー(手動) | ぽこが今までどおり StreamDeck で付ける。配信後に Get Stream Markers(`video_id` 指定)で読む | `position_seconds`(配信の先頭からの秒)が API で返る |
| ② | チャネポ「クリップ希望」の交換 | EventSub `channel.channel_points_custom_reward_redemption.add`(`reward_id` で絞る)を pokonya で受ける | `redeemed_at`(UTC) |
| ③ | DbD の画面認識 | 試合開始時の **左下のマップ名**、リザルト画面の **キラー名** と **脱出人数** を読む(§4) | ぽこの PC で画像を撮った時刻(UTC) |

- ①は既存の運用をそのまま使う(新しい操作を増やさない)。マーカーを付けるのは StreamDeck の Twitch 連携で、このツールはマーカーを **読むだけ**
- ②の `user_input`(視聴者が書いた一言)があれば一覧に出す
- ③は DbD 以外のゲームでは動かない。DbD 以外の配信は①②だけで動く
- 配信の区切りは EventSub `stream.online`(配信 ID `id` と `started_at`)と `stream.offline` で取る。pokonya は今 `stream.offline` だけ購読しているので `stream.online` を足す。`stream.offline` には配信 ID がなく、Get Stream Markers の `user_id` 指定は「直近の 1 本」しか返さないため、`stream.online` の配信 ID で VOD を特定する

### 2.1 時刻をそろえる
- すべて UTC の時刻で記録し、配信後に VOD の先頭からの秒(VOD オフセット)に直す
- VOD は Get Videos(`user_id`、`type=archive`)のうち、`stream_id` が `stream.online` の配信 ID と一致するもの。換算の基準は VOD の `created_at`
- 入力ごとに時計がずれる向きが違うので、**補正量は入力の種類ごとに持つ**(値は実測して決め、設定で直せるようにする):
  - ①: 配信のタイムラインそのもの。マーカーの `created_at` と `position_seconds` から「VOD の `created_at` と実際の先頭のずれ」が分かる。マーカーがない配信は `created_at` だけで換算する
  - ②: 視聴者が見ていた時刻なので、配信より **遅い**(視聴の遅延 数秒〜十数秒 + 押すまでの時間)。その分を引く
  - ③: ぽこの PC の時刻なので、配信より **早い**(エンコードと送出の 1〜3 秒。OBS の「配信遅延」を使っていればその秒数も)。その分を足す
- ③は PC 側で撮った時刻を付けて送る。pokonya は受け取った時刻も記録し、差が大きければ(PC の時計のずれ・再送)一覧に注意を出す
- 配信が途中で切れて VOD が分かれた場合は、時刻で属する VOD を決め、補正量も VOD ごとに計算する。分かれ方は実機で確かめる
- Twitch の VOD には保存期間がある(アカウントの種類で 7 / 14 / 60 日)。VOD リンクとクリップを作るボタンはその期間だけ使える。一覧とタイムスタンプ文は VOD が消えても残る

## 3. 出力
配信が終わったら、次の 2 つを作る。

- 起点は `stream.offline`。ただし短い切断のあと再接続すると `stream.offline` → `stream.online` が続けて届くので、**`stream.offline` から 10 分(仮)待ち、その間に `stream.online` が来たら同じ配信の続きとして扱う**。出力は 1 配信 1 回
- 待つ間に VOD の `duration` が確定しているかは実機で確かめる

### 3.1 クリップ候補の一覧
- 1 行 = 1 候補: VOD オフセット(`1:02:03`)、手がかりの種類(①②③)、内容(マーカーの説明 / 交換した人と一言 / マップ・キラー・脱出人数)、VOD をその時刻で開くリンク(`https://www.twitch.tv/videos/<id>?t=1h2m3s`)
- **提案(サジェスト)**: 近い時刻の手がかりを 1 つにまとめ、重みを付けて並べ替える。例: 60 秒以内に「クリップ希望」が 3 件以上 → 上位、全滅 / 全逃げの試合の終わり → 上位
  - 重みの付け方は v1 では単純な足し算にし、ぽこが使ってみて直す
- クリップを作るボタン(v1 に入れるかは未決事項 B3): Create Clip From VOD(`vod_offset` は **クリップの終わり**、長さ 5〜60 秒、既定 30 秒)

### 3.2 YouTube 概要欄用のタイムスタンプ文
```text
0:00 開始
1:45 死んだ犬の酒場 vs レイス(2 人脱出)
24:10 石炭の塔 vs ナース(全滅)
```
- DbD の試合ごとに 1 行。書式は `<時刻> <マップ名> vs <キラー名>`(脱出人数を付けるかは未決事項 P3)
- 時刻の基準は試合開始(マップ名を認識した時刻)。①のマーカーが近くにあれば、マーカーの時刻を優先する(ぽこがマッチ開始で押しているため)
- YouTube のチャプターの条件(YouTube ヘルプ、2026-10-22 確認): 最初が `00:00`、3 つ以上を昇順、1 つ 10 秒以上。先頭に `0:00 開始` を必ず入れ、10 秒未満の間隔の行は 1 つにまとめる。試合が 1 つだけの配信はチャプターにならない(文としては出す)
- YouTube に上げる動画が Twitch の VOD を **切らずに** そのまま上げたものか、先頭を切ったものかで時刻がずれる。全体をずらす設定(例: `-0:35`)を付ける(未決事項 P4)
- 文はコピーボタン 1 つでクリップボードへ

### 3.3 どこに出すか(未決事項 B1)
- 推奨: **pokonya が Discord のぽこ用チャンネル(非公開)に送る**。ぽこは画面操作だけで受け取れ、hoshino-poko.com が止まっていても使える
- 代わり: poko-tools のパネル(配信後に開いて読む) / pokonya の管理画面

## 4. DbD の画面認識

### 4.1 何を読むか
| 場面 | 読むもの | 備考 |
|---|---|---|
| 試合開始(読み込み後) | 左下のマップ名(例「死んだ犬の酒場」) | 「領域名 — マップ名」の形で数秒〜十数秒出る(と思われる。実機で確認)。決まった一覧(数十件)の中から一番近いものを選ぶ。自由な文字の読み取りより外れにくい |
| リザルト画面 | キラー名、脱出人数 | 画面に **キラーのキャラ名が文字で出るか** は未確認(プレイヤー名が主で、キャラ名は小さい / 匿名モードの相手はキャラ名表示になる、という認識。確信度は低い)。文字で出ないなら顔の画像の照合か、ぽこが選ぶ方式になる(未決事項 B5)。脱出・処刑・切断はアイコンなので、脱出人数は **アイコンの照合** で数える |

- マップ名・キラー名の一覧は同梱する。キラーのキャラ名は dbd-perks が使っている dbd.tricky.lol の `/api/characters` から取れる。マップ(領域名を含む)の一覧の出どころは未確認。AGENTS.md に従い dbd-perks のファイルは参照せず、このツール用に書き出す
- 公式の画像は同梱しない(照合に画像が要る場合は、ぽこの PC で撮ったものをその場で登録する方式)。BHVR のファンコンテンツ規約(非商用)に従い **この機能は無料**(dbd-perks と同じ方針)

### 4.2 どの映像を読むか
- **OBS のゲームソース単体** を読む。ぽこの配信レイアウトでは左下がパーク表示で隠れるため、配信の出力(番組)は使わない(2026-10-21 合意)。ソース単体の画像はシーン上のクロップ・重なりの影響を受けない
- 同じ理由で、勝敗カウンター(`win-loss-counter.md`)もソース単体を読む
- 前提: **ゲームキャプチャは、どのシーン(またはプレビュー・プロジェクター)にも映っていないと取り込みを止める**(obs-studio の game-capture は `obs_source_showing()` が偽のとき止まる)。別のシーンに切り替えている間は画像が空になり認識できない。ゲームソースを配信中のシーンにずっと置く(上に重なっていてもよい)運用が要る(未決事項 P8)
- 案 A(ブラウザソース)の場合、そのブラウザソースも配信中ずっと動いている必要がある。全シーンに置くか、ソースの「シーンがアクティブでないときにソースをシャットダウン」をオフにする

### 4.3 方式の比較(未決事項 B2)

| 案 | 仕組み | 良い点 | 気になる点 |
|---|---|---|---|
| A. ブラウザソース + obs-websocket + tesseract.js | poko-tools のページが OBS の obs-websocket v5 につなぎ、`GetSourceScreenshot`(ゲームソースを縮小して取る)で 1〜2 秒ごとに画像を取り、ページの中で切り出して文字を読む | 追加のインストールがない。obs-websocket の接続・パスワードの扱いはデコポコのスポイト(`docs/architecture/deco-poko-obs-vts.md`、PR #49)と同じ | tesseract.js は Worker と学習データ・wasm を `fetch` で読むので **file:// ではそのままでは動かない**。JS に埋め込めば回避できるが日本語の学習データが数 MB〜十数 MB あり zip が大きくなるので、実質 GitHub Pages 版だけになる。ゲームの装飾フォントの読み取り精度は未知。OBS の負荷を実測する必要あり |
| A'. 案 A + 画像の照合(OCR なし) | 文字を読まず、ぽこの PC で登録した見本画像と、切り出した範囲を比べる | 軽い・file:// でも動く | 見本の登録をぽこにしてもらう手間。マップが増えたら登録し直し |
| B. ローカルの Python エージェント | ぽこの PC で常駐する小さなアプリが obs-websocket で画像を取り、OCR(Windows 標準の OCR / Tesseract / PaddleOCR など)で読み、結果を pokonya に送る | OCR の選択肢が広く速い。ブラウザの制約がない | ぽこの PC へのインストール・更新が要る(exe にして配る)。非エンジニアのぽこが起動を忘れると何も残らない |
| C. OBS プラグイン Advanced Scene Switcher | プラグインの「映像」条件(画像の照合 / 文字の読み取り)で場面を見つけ、結果をこのツールに知らせる | 認識の部分を作らずに済む | プラグインの導入が要る。知らせる手段が回りくどい。機能・ライセンスは未確認 |

- 推奨(ドラフト): **まず案 A を実験ページで試す**(取得の負荷・マップ名の読み取り精度・リザルトに出る文字)。精度が足りなければ A'、それでも駄目なら B に切り替える
- 共通: 一度認識したら同じ場面を二重に数えない(同じ結果が続いたら確定し、画面から消えるまで次を数えない)
- 認識した時の画像(縮小したもの)を候補の一覧に添えるかは未決(誤認識の確認用。保存先と容量の問題)

## 5. 全体の形(ドラフト)

```text
ぽこの PC                                   cnh-vps pokonya-api            Twitch
OBS ── obs-websocket(localhost)             │                              │
  │ GetSourceScreenshot(ゲームソース単体)   │                              │
  ▼                                          │                              │
見どころメモ(ブラウザソース / 案 B なら常駐) │ ←── ③ 認識結果を POST ─────  │
                                             │ ←── ② EventSub webhook ───── │ チャネポ交換
                                             │ ←── stream.online / offline ─ │ 配信の区切り
                                             │ ──→ Get Stream Markers ────→ │ ①
                                             │ ──→ Get Videos(VOD)───────→ │
                                             ▼
                                   Discord(ぽこ用チャンネル): 候補一覧 + タイムスタンプ文
```

- ③の送り先は pokonya。ブラウザソースから送るときの認証(OBS 用の URL トークンなど)は設計で決める。hoshino-poko.com のページは使わない
- 案 A のブラウザソースは GitHub Pages(https)から `ws://localhost` につなぐことになる。つながるかはデコポコの段階 a の確認事項と同じ(`deco-poko-obs-vts.md`)
- ぽこが連携を外す・Twitch のパスワードを変えると EventSub の購読が `authorization_revoked` で止まる。pokonya はその通知を受けたら Discord で ぽこに連携し直しを頼み、購読を作り直す

## 6. Twitch API・スコープ(2026-10-22 公式 docs で確認)

| 使うもの | 認可 | 用途 |
|---|---|---|
| EventSub `channel.channel_points_custom_reward_redemption.add`(v1) | `channel:read:redemptions` または `channel:manage:redemptions` | ② 交換の受け取り。condition は `broadcaster_user_id`(必須)と `reward_id`(任意) |
| EventSub `stream.online` / `stream.offline`(v1) | 不要 | 配信の区切りと配信 ID(`stream.offline` は購読済み) |
| Get Stream Markers `GET /helix/streams/markers` | user token、`user:read:broadcast` または `channel:manage:broadcast` | ① マーカーの読み取り(`video_id` で VOD を指定。`user_id` なら直近の VOD。1 ページ最大 100) |
| Create Stream Marker `POST /helix/streams/markers` | user token、`channel:manage:broadcast` | **v1 では使わない**(StreamDeck が付ける)。③の認識時に自動でマーカーも付けるなら要る(未決事項 B4)。VOD 保存がオフ・配信していない・再放送のときは付けられない。説明は 140 文字まで |
| Get Videos `GET /helix/videos` | app token または user token | VOD の ID・`created_at`・`stream_id`・`duration` |
| Create Clip From VOD `POST /helix/videos/clips`(NEW) | ぽこの user token、`channel:manage:clips`(編集者として作るなら `editor:manage:clips`) | 候補からクリップを作る(v1 に入れるかは未決事項 B3)。`editor_id` はトークンのユーザーと一致が要る。**404 の説明に「配信中でなければならない」とあり**、配信後に作れるかは実機で確かめる |
| (参考)Create Clip `POST /helix/clips` | user token、`clips:edit` | 呼んだ時点の前後約 90 秒から作る。配信後の候補には使えないので使わない |
| (参考)Create Custom Rewards | user token、`channel:manage:redemptions` | 「クリップ希望」を API で作る場合だけ(§7) |

- 必要最小のスコープ(v1): `channel:read:redemptions`、`user:read:broadcast`。クリップを作るなら `channel:manage:clips` を足す。自動でマーカーを付けるなら `channel:manage:broadcast` を足す(`user:read:broadcast` の代わりにもなる)
- pokonya の Twitch OAuth は今 `chat:read chat:edit` だけ(`auth/router.py` の `SCOPES`)。スコープを足して **ぽこに連携し直してもらう**(`/auth/twitch/start`)必要がある
- pokonya の EventSub は webhook + app access token(`utils/register_eventsub.py`)。webhook の購読には、配信者がそのアプリに必要なスコープを許可済みであることが要る(許可がないと購読が作れない)
- マーカー・VOD 関連は **ぽこの VOD 保存がオン** であることが前提

## 7. チャネポ「クリップ希望」
- 報酬は ぽこが Twitch の管理画面で作る / pokonya が API で作る のどちらか(未決事項 B6)
  - Twitch の仕様で、交換の状態(完了・返金)を API で変えられるのも、報酬の有効化・一時停止・編集を API でできるのも **報酬を作ったアプリだけ**。管理画面で作ると pokonya からは触れない(配信の外では ぽこが手で一時停止する)。配信外の交換を自動で返金・一時停止したいなら pokonya で作る(`channel:manage:redemptions`)
- ポイント数・1 配信あたりの上限・クールダウン・一言の入力の有無はぽこが決める(未決事項 P2)
- チャネポの報酬は 1 チャンネル最大 50 個(有効・無効を含む)
