## 3. 自動カウント

### 3.1 何を読むか
| ゲーム | 読むもの(例) | 備考 |
|---|---|---|
| OW | 試合終了の「VICTORY」「DEFEAT」「DRAW」(日本語クライアントの表記は実機で確認) | ぽこの OW の表示言語を確認(未決事項 P2) |
| ポケモン | 対戦の勝ち・負けの表示 | **どのタイトルか**(ユナイト / SV のランクバトル など)で画面がまったく違う(未決事項 P2)。Switch はキャプチャーボードの映像ソースを読む |
| (あとから)ほかのゲーム | ゲームごとに「読む範囲・文字 / 見本画像・勝 / 負 / 分のどれか」を登録 | ゲーム用の設定は JS 定数で同梱する(file:// で `fetch` しないため) |

- 読む範囲は画面の決まった場所(例: 中央上)を割合で切り出す。ゲームの解像度が変わっても同じ割合。ソース単体の画像はシーン上のクロップ・変形の前のものなので、OBS でゲームソースをクロップしていても割合はずれない
- 判定は「決まった語(VICTORY / DEFEAT など)のどれに近いか」。自由な文字の読み取りより外れにくい

### 3.2 どの映像を読むか
- **ゲームソース単体**(ゲームキャプチャ・映像キャプチャデバイスなど)。パネルで OBS のソース名を選ぶ
- 取り方・方式の比較は見どころメモ `stream-moments.md` §4.3 と同じ(obs-websocket `GetSourceScreenshot` をブラウザソースから / ローカルの Python エージェント / OBS プラグイン)。勝敗は語の数が少ないので、**見本画像の照合(案 A')** だけで足りる可能性が高い(file:// でも動く)
- 前提: **ゲームキャプチャは、どのシーン(またはプレビュー・プロジェクター)にも映っていないと取り込みを止める**。別のシーンに切り替えている間は画像が空になり数えられないので、ゲームソースを配信中のシーンにずっと置く(上に重なっていてもよい)。映像キャプチャデバイス(キャプチャーボード)は既定の設定なら映っていなくても取れる(「表示されていないときは無効化」がオフの場合)
- ブラウザソースで動かす場合、そのソースも配信中ずっと動いている必要がある(全シーンに置くか、「シーンがアクティブでないときにソースをシャットダウン」をオフ)

### 3.3 二重に数えない
- リザルトは数秒〜十数秒出続ける。**同じ判定が N 回続いたら確定**し、その文字が画面から消えるまで(または一定時間)次を数えない
- 試合の途中の「VICTORY」(リプレイ・ハイライト・他人の画面)で数えないよう、読む範囲と確定の条件をゲームごとに持つ

## 4. 手動補正
- パネルに 勝 / 負 / 分 それぞれの `+1` `-1`、全部 0 に戻す(確認あり)
- **直前の自動カウントを取り消す** ボタン(誤検出用)。自動で数えた記録(時刻・判定・どのくらい自信があるか)をパネルに 10 件ほど出し、1 件ずつ取り消せる
- 自動カウントの一時停止(カスタムマッチ・練習中など)
- StreamDeck から補正する口は未決(未決事項 B4)。OBS の対話ではキーが OBS 本体に吸われることがあるので、キーボードのショートカットには頼らない(dbd-perks と同じ理由)
- 保存は localStorage(`poko-win-loss-v1`)。`?id=<名前>` でキーを分ける(ゲームごと・日ごとにカウンターを分けたいとき)

## 5. 見どころメモとの関係
- 勝敗の確定はそのまま「見どころ」の手がかりになる(試合の終わり)。見どころメモに勝敗を送るかは、見どころメモの方式(`stream-moments.md` 未決事項 B2)が決まってから
- DbD の「脱出人数」は勝敗カウンターでも数えられる(例: 4 人脱出 = 勝ち)が、v1 の対象ゲームには入れない(BHVR の規約で DbD 関連は無料のみ。配り方が決まってから)
